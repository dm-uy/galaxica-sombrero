# Lints

Mechanical checks establish bounded properties of actual inputs. Their engines, launchers, language recognizers and
permission mechanisms are runtime adaptations through {{cap:check-runner}}; naming a check does not install it. This
subject completes the neutral checker contracts alongside [tests](../code/tests.md), without replacing independent
source, converse, annotation-truth or result review.

<!-- anchor: checks.lints.evidence -->

## Applicability, populations and outcomes

- **LINT-101** MUST: For each claimed check state its actual trigger, input identity, bounded population and exclusions, prerequisites, command/arguments, working directory, stdout/stderr, exit and recognized coverage. Identify the owner and recognizer limits. Actual declarations and executed evidence are different facts; report text reads separately from dynamic execution.
- **LINT-102** MUST: Distinguish a runnable clean result, a violation and a check that could not run. Missing, unreadable, empty-required or unrecognized inputs cannot become clean coverage. The source CLI profile uses exits 0/1/2 for clean/violation/could-not-run; preserve the actual declared interface, including current conform's existing statuses and refusal precedence, without adding wire enums. Applicability exclusion needs a genuinely false trigger and reason; unavailable required evidence remains unverified.
- **LINT-103** MUST: Establish a claimed property with meaningful positive, intended-defect negative, contrary/true-loss and equivalent-retention controls where applicable. Inspect full contexts and preserve compound required counterparts physically. Restore the exact owned defect fixture and recheck the property. Actual visited population, not marker starts or a fixed quota, defines coverage. Do not alter an original source to manufacture green or substitute regex presence for independent constituent-level meaning review.
- **LINT-104** MUST: If a command's stdout, stderr or exit is a promised delivery channel, exercise its real launcher and observe that channel. Pure library records and pure rendering have separate obligations; a local function return or mock does not prove a process exit or a silent delivered stream. Verify advertised exports against actual symbols and keep shared traversal/aggregation ownership truthful.

## Visual gate and requirement declarations

- **LINT-201** MUST: Use the unchanged visual-gate activation and [development-plan](../protocols/dev-plan.md) and [graph](../protocols/graph.md) contracts. Check actual changed node definitions rather than reference/link or metadata furniture. A definition with missing, empty or only non-business-requirement satisfaction is scope creep; an undeclared requirement reference and an approved requirement with no covering node are distinct failures. Missing graph/spec prerequisites or zero recognized required definitions cannot prove coverage.
- **LINT-202** MUST: Reconcile recognized business-requirement declarations with the approved population. Distinguish an actual heading/list/ordered-list declaration from a mid-line prose mention; state supported separators, quotation and suffix grammar. Legacy any-mention sweep or loose fallback only when no declaration is recognized is a bounded source behavior, not proof every approved requirement was found.
- **LINT-203** MUST: Disclose profile differences: suffix-based module/class/function/method scans may miss unsupported definitions, broader requirement-bearing tag scans may deduplicate occurrences, and broad list furniture can admit false declarations. A forgiving regex scan of partial/unescaped text does not prove canonical XML parse/render fidelity. Do not import a runtime's arbitrary-tag dialect into protected canonical graph grammar.

## Preserve the quality bar across the actual work

- **LINT-301** MUST: Before committing, inspect the actual work against an explicit run-start base, including additions, removals and untracked content. Check introduced suppressions, skips, unfinished work, compact empty catches, deleted assertions/test functions/test files and numeric weakening. Report hits and advisory classes rather than waive a report wholesale; an empty postcommit HEAD diff says nothing about the earlier work. Invalid base, Git failure or unreadable content cannot prove clean work.
- **LINT-302** MUST: When comparing thresholds, pair only the same intrinsic metric or the phrase's own normalized span, keeping those namespaces separate. Report total/keyed/unkeyed/compared/skipped populations and unmatched or incomparable inputs. Carry comparator direction: reducing a lower bound or raising an upper bound loosens it; any exact-value change needs a reported direction/decision; genuine tightening of a directional bound does not count as loosening. Comparator-class changes and unsupported or multiple thresholds require actual semantic judgment, not arbitrary pairing through an empty shared key.
- **LINT-303** MUST: Disclose bounded numeric recognition and pairing. The retained profile recognizes a finite vocabulary, short lookaround, restricted number/noun syntax and last-row comparison; equal-number comparator-class changes or earlier thresholds can escape it. A separately recorded source numeric-deletion detector reverses a comparison direction. Preserve the intended anti-weakening duty, route that engine defect to its runtime owner and do not claim universal detection or port/fix the engine here.
- **LINT-304** MUST: For detector denoising show both lost and gained detection sets over a fixed meaningful population, retaining genuine positives while removing false positives. Net totals alone do not prove preservation. Disclose line-only compact-catch, syntax/language, own-source self-collision and escaped-pattern/literal-lockstep limits. Changes to escaped source notation must retain the intended compiled recognition and its applicable positive/negative evidence.
- **LINT-305** MUST: Keep diagnostics safe under the target privacy contract. A source profile's documentation findings are advisory and exit-neutral while code/test findings fail; this does not waive substantive source review. The recorded guard prints source excerpts despite its no-secret promise, so neither its reassuring header nor a green shallow scan constitutes security proof. Existing privacy and isolation guards are distinct mechanisms, not replacements for bar review.

## Bidirectional declaration accounting

- **LINT-401** MUST: Compare actual and declared publication, exclusion, census and permitted-path membership in both directions. Report omitted actual members, stale declarations and unreadable/unparsed inputs. Inspect declaration source text without importing test modules, whose module-level execution is outside a reporter's read-only duty. Record relevant assignment form and source population; a declaration is not a copied reassuring total.
- **LINT-402** MUST: Disclose reporter scope gaps such as missing-module skips or a repeated same-name list in another module being ignored. A symmetric claim cannot rest on a one-direction or partial census. Detailed paired code-point notation, encoded-pattern/quoted-data/position-marker exemptions and their measured symmetric membership profiles are supplied in [prompt markup](../prompting/prompt-markup.md) and [language](../policies/language.md); concrete publication implementation remains a later duty and comparable measurement belongs to review/learning. Historical source counts are not current verification.

## Markup presence, library and CLI boundaries

- **LINT-501** MUST: State actual visited language/file/entity populations for region pairing/nesting, function/method purpose-I/O-complexity, class purpose, applicable module contract/nonempty summary/structure and valid importance/function/block payload checks. Apply the owning [exoskeleton](../code/exoskeleton.md) edit locality and [LDD](../code/ldd.md) encoding, rather than demand whole-file retrofit from a source scorer's header.
- **LINT-502** MUST: Disclose invisible unmarked entities, nested-method skipping, bracket-only or one-logger recognition, structured-log omissions and bounded lookahead that can borrow a neighboring payload. Presence in the recognized population does not establish annotation truth, whole-population compliance, correct runtime trajectory or a successful documentation build.
- **LINT-503** MUST: Keep pure record generation, shared traversal/single aggregation, public package exports and shim internal aliases distinct. Observe actual CLI rendering and exit/read-failure behavior when promised. A historical silent-stream or import-bootstrap contract is local runtime context; it grants no universal no-LDD exception, logging waiver or path-hack permission for methodology-authored code.

## Maps and old-form coverage

- **LINT-601** MUST: When checking map claims, measure entities, resolve links and reconcile claimed coverage, declared deliberate omissions and source/configuration freshness. Structural equality and a green build do not prove annotation truth. A source backlog proposal for an installation drift guard is an owed implementation, not evidence an operational guard exists.
- **LINT-602** MUST: For an old-form detector state the actual root configuration, covered Python files, old summary/structure and block-alias forms, unreadable count and text-recognition limits. A text scan is not AST or documentation-parser proof. Missing configuration is an unavailable prerequisite where a map is required, not a universal exemption. Apply an actual migration command only under separate authorized edit scope and the owning safe [migration rules](../code/exoskeleton.md).

## Detailed lifecycle and deferred runtime permission homes

- **LINT-701** MUST: Retain the decision checker's bounded applicability/population/outcome/limits with detailed decision lifecycle now authored in [decisions](../process/decisions.md) and its specification interface retained in [specification](../process/specification.md). Owning source duties include ordered Status → Context → Decision → Alternatives → Consequences, real named alternatives or the exact missing-preprotocol-history escape, fixed/open-trigger/superseded-successor/rejected-reason obligations, bidirectional index and open-register no-code/per-axis-trigger rules. A status prefix, trigger word or named alternative proves syntax/presence, not truth or quality; this checker body neither invents a competing lifecycle schema nor certifies substantive lifecycle truth or quality.
- **LINT-702** MUST: Retain parent-owned role transitions and declared {{cap:role-permissions}}. A concrete seven-playbook preflight with last-match-wins permissions, blanket-deny-before-exceptions ordering, task/skill denies and fatal-tier failure remains a runtime permission profile; it is not a universal ban on loading protocols. Test its negatives only in owned injected resources. Do not edit original roles or transplant a deny-skill policy into a runtime that requires protocol loading.
- **LINT-703** MUST: Keep detailed notation/prompting in their current authored [prompt markup](../prompting/prompt-markup.md), [prompting](../prompting/grace.md) and [language](../policies/language.md) homes; comparable evaluation/learning and concrete browser/database/guard/parser/scorer/migration/install/deploy engines remain in their explicitly owning later subjects or adapters. Generic checker evidence here does not complete those bodies, operational adoption or full-source synthesis. Review unsupported source-dependent duties as unresolved, rather than infer their absence from this bounded packet.
