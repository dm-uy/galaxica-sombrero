<Whose problem is solved, and what concrete outcome matters?>

<Binding constraints and explicit scope boundaries; link owner authority.>

<Outcome, reason and return condition; none if empty.>

<Canonical intent layer/path; project metadata/status/reader/writer/update event; adopted conventions identity; link entry and route. Preserve existing requirement/parity documents if any.>

## Complete fictional filled example

Every person, approval, revision, source, result and observation below is invented for **Meadow document review**. This is a complete illustrative record, never actual consent or project evidence. Paths name the five imagined records; evidence bodies are embedded in them.

````markdown
---
type: Vision
title: "Meadow document review — purpose"
status: approved
generated: { by: "fictional coordinator", at: "2026-01-12T09:00:00Z" }
---

# Goal and users

The Meadow editorial owner needs a qualified review of two internal guidance passages so reviewers can distinguish supported statements from missing evidence. The outcome is a review table with source identity, limitation and disposition per passage; the owner then decides whether to publish.

# We are there when

P1 inventory is retained and P2 has a reviewable disposition for both passages, each checked by a reader who did not draft it. Delivery evidence lives in TASKS.md#retained-records. Missing passage S2 prevents the complete review claim. Publication and later reader comprehension are separate outcomes; neither is proven by a finished table.

# Constraints and non-goals

Authority is the imagined B-002 grant in TASKS.md#grant-record, with scope limited to five local records and their embedded source/results. Preserve failed B-001 history and every source qualification. Contacting readers, publishing or changing the purpose is reserved. No software delivery, live environment or model comparison belongs to this project.

# Deferred

P4 reader interviews are held: contact is outside B-002. Return when the owner grants contact and a question set is prepared; retained T-204 lives in TASKS.md. The deferment does not remove the outcome from the route.

# Authority and profile

The fictional owner accepted this purpose on 2026-01-12; the complete imagined statement is in TASKS.md#grant-record. Canonical intent is root VISION.md under AGENTS.md's single-layer meadow-records-1 profile. Owner directs goal changes; coordinator writes them; owner/reviewer read this record. No neutral metadata card is imposed on these project records.

# Source snapshot

Observed at the imaginary meadow-r2 snapshot, 2026-01-12: S1 version 1 body is “A reviewer records the passage and the evidence it cites before assigning a disposition.” S2 is absent, with no verified revision or body. These are fictional document inputs, not fetched quotations. No full corpus or source completeness claim follows. Inventory/result retained in TASKS.md#retained-records; route points here without absorbing this observed-state role.

# Idea pool

Future idea I1: test whether readers understand the review. No task is activated. Return after P3 owner disposition and a separate research grant. This is an idea pool, not the observed source snapshot and not a second roadmap.

# Evidence and uncertainty

P1 has an inventory result in TASKS.md. P2 is active and incomplete: T-202 has a recoverable draft, T-203 lacks S2. No independent complete-table assessment has run. A hoped-for reduction in misunderstanding is unmeasured. Writing “ready” into metadata would supply no proof and must leave the readiness conclusion unsupported.
````
