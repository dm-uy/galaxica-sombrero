## Invocation and authority

The real standalone process is `python3 -B implementations/codex/hooks/guard_destructive.py --policy POLICY --policy-sha256 POLICY_SHA --handler-sha256 HANDLER_SHA`. Resolve all three pins to literal parent-authenticated values before invocation. Standard input is exactly one UTF8 JSON object of at most65536bytes; policies have the same limit. No environment variable selects policy, hashes, role or grant. Missing/malformed/changed binding or input returns exit2 with safe stderr. A recognized refusal emits PreToolUse hookSpecificOutput/permissionDecision deny with a fixed reason, exit0. A permitted event exits0 with empty stdout: **no-veto means no added hook veto, never native allow, owner consent or escalation**. Arguments are never rewritten; PermissionRequest is not handled.

The parent authenticates invocation provenance, policy/handler hashes, source definition and separately rendered definition/trust. A policy's grant string and filesystem readonly mode cannot authenticate themselves. Calling the helper with self-chosen argv outside the reviewed route proves no guard authority. Source-stage fixtures record literal argv/cwd, pins, rendered-definition hash, streams/exit and immutable source observations outside fixture worker effects. These receipts are synthetic, never host trust.

## Exact policy grammar

Version1 policy is a JSON object with exactly: version (plain integer1), profile (readonly or writable), grant/session_id (nonempty strings), source_roots/protected_roots/git_roots/worker_write_roots/scratch_roots/evidence_roots (unique arrays of normalized absolute nonlinked existing paths), effects, binding and checks. Duplicate/unknown fields and booleans masquerading as integers refuse.

Each effect has exactly path, operations (nonempty unique array from read/create/write/delete/mode), recursive (plain bool). Effects must be inside worker_write_roots. A write to an absent entry requires both create and write; implicit missing parents each require their own create coverage. A write-only grant permits existing entries only. Scratch/evidence effects cannot create or address .git. There are no global cache/temp/regenerable exemptions. protected_roots and git_roots forbid direct reads/writes; source_roots permit ordinary reads and are immutable under readonly profile. Scratch/evidence roots must lie under worker roots, have no linked descendants and no .git in their ancestry or descendants. Readonly is session-wide for every intercepted actor, not authenticated per-subagent QA identity.

binding has exactly policy_path/policy_mode, handler_path/handler_mode, definition_path/definition_mode/definition_sha256, entries. Policy and handler hashes are external argv pins. Each entry has exactly path/type/mode/device/inode; type file or directory. The population is exactly the three binding files and their immediate entry parents, without duplicates. Regular binding files must have one hard link; policy has no write mode bits. Metadata and hashes are verified before decisions. Effect resolution also protects known inode aliases, entry replacement/chmod and recursive ancestors. Path resolution rejects symlinks, unknown expansions and noncanonical absolute paths. Binding/worker overlaps refuse; parent entry protection does not prohibit unrelated descendants automatically. Races remain possible: this is no OS confinement.

checks is a list of exactly {command,cwd,files,effects}. A recipe matches literal command and canonical cwd only; each file record is {path,sha256,mode}, each effect {path,operation} must already be granted. Every file pin is checked. Read-only recipe inputs may be multiply linked regular system files (the measured /usr/bin/git has multiple links); binding files remain single-link and every addressed effect on multiply linked files still refuses. Recipes are explicit parent authentication of opaque checks and their effects, not proof that Python/pytest prefixes are confined. A malicious parent-approved recipe is outside the kernel's authority claim. Unknown/changed recipes fall through finite parsing or refuse; no candidate command executes inside the guard.

## Event and supported effects

Required fields: hook_event_name PreToolUse, matching session_id, cwd existing canonical directory, tool_name and tool_input object. Optional string-only metadata: turn_id/tool_use_id/model/permission_mode/transcript_path; transcript paths are never opened. Unknown role/roots/approval fields refuse. Bash tool_input has command and optional description/workdir strings and positive plain timeout_ms integer. workdir resolves before classification. apply_patch has command only.

cp/mv support exact regular-file source only; an existing directory destination is resolved to its effective basename child. Directory copies/moves and their recursive flags remain unsupported rather than undercount descendants.

Finite shell support includes every simple command in semicolon/newline/&&/|| chains conservatively, static redirects, literal cd where no conditional cwd ambiguity, quoted paths, quoted heredoc data owned by cat, and nested sh/bash -c to depth2. All variable expansions and environment assignments refuse, including assignment-only forms: quote removal/word splitting and PATH/IFS/loader semantics are not proved. This conservative narrowing preserves ordinary static paths. Unknown control-flow/interpreter/pipeline/xargs/subshell semantics refuse. Closed read forms cat/ls/stat/rg (directory traversal bounded to1024entries and all protected descendants checked), echo without flags and printf limited to an exact %s format and one argument, static file operations touch/mkdir/cp/mv/tee/chmod/rm and finite find deletion require complete path/effect checks. Unknown flags refuse. Supported syntax is intentionally smaller than a general shell; no full Bash compatibility claim. Parent-pinned recipes supply explicitly authorized opaque checks.

Git mutations (force/ref/config/index/object/fetch/commit/checkout/restore/reset/clean/worktree and unknown verbs) refuse, even a clean source tree. Git status/diff/log/rev-parse/show have a closed discovery grammar but require exact parent-pinned check recipes for no-veto: local fsmonitor/textconv/external-diff/pager configuration can execute code. Generic Git reads remain refused even after successful discovery. Explicit -C/--git-dir/--work-tree addresses are reconciled against fixed `/usr/bin/git rev-parse` store probes, controlled environment, timeout3, no optional locks, bounded captured result. Failure or unknown store refuses. No candidate Git command runs. Writable Git mutation lacks reliable implemented resource/state proof and remains refused, never silently permitted. Dirty source/index/untracked/ignored and metadata are preserved; `git status` alone is not proof of metadata purity.

SQL clients, scripts and pipelines refuse because actual resource/semantics are unsupported. A quoted cat heredoc containing DROP text is data; its static output redirect still needs grant. apply_patch requires Begin/End Patch and recognized Add/Delete/Update/Move headers; every old/new addressed path is checked, update requires write/delete grants. Patch content is data; invalid shape/escape/link refuses. No SQL, patch or destructive command is executed to classify it.

## Binding source and limits

hooks/hooks.json contains one synchronous catch-all PreToolUse handler with timeout10, no async/allow/ask/approval/rewrite/trust/error-swallowing. Manifest points at that exact contained file. The shipped command invokes `python3 -B "$PLUGIN_ROOT/hooks/guard_destructive.py"` without policy pins and therefore refuses if loaded unbound. PLUGIN_ROOT is a documented proposed host locator, not policy authority. Parent-controlled source-stage tests render a separate exact definition with literal pins and keep its immutable independent receipt outside worker effects. Native activation must review/select the bound definition instead of concurrently loading the shipped unbound definition; multiple matching hooks may run concurrently. This requires its separate exact AC7/C6 decision.

Supported source-stage channels: direct kernel and actual standalone stdin/process stdout/stderr/exit; synthetic Bash/apply_patch events only. Proposed/unverified: native event names/ABI, plugin loading, hash-specific host trust, nested host tool calls and actual before-effect interception. Unsupported/unproven: write_stdin continuation to existing processes, specialized/MCP/hosted tools, hook launch/timeout/fault fail-open behavior, authenticated per-agent identities and whole-system secret/resource confinement. An untrusted, stopped, missing or failed hook does not earn readiness; internal deliberate parser/binding errors deny, but externally failed launch cannot be fixed by this handler. Native AC7 requires actual captured events and canary target readback with independent claimed Git metadata comparison. Standalone tests fulfill none of AC7.
