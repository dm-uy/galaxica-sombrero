# Doxygen map

This contract describes applicable source authoring and evidence duties under the target rules. Actual runtime mechanisms remain declared adaptation points; textual completion supplies no operational adoption claim.

<!-- anchor: code.doxygen.build -->

## Mandatory configuration and final build

- **DOXY-101** MUST: Provide the actual Doxyfile/tool prerequisites at bootstrap, preserve authorized covered-source/exclusion configuration, and finish every code task and finalization with an actual Doxygen build after passing tests and documentation fixes under target rules. Missing configuration/tool is an owed requirement and unavailable evidence, never clean PASS. The sole exception requires an explicit written target prohibition, quoted with applicability. XML generation is mandatory unless explicitly prohibited; HTML presentation is optional. Ignored XML output is rebuilt rather than committed; a second map owns its separate configuration/output. Navigation readers request parent-owned refresh rather than writing inspected trees.

<!-- anchor: code.doxygen.freshness -->

## Complete covered-source currency

- **DOXY-201** MUST: Derive covered sources and output/index from actual configuration. A fresh map has an XML index newer than EVERY covered source, with current source/config identity also pinned. Distinguish no sources yet, not built, fresh, in progress and stale. All newer files being uncommitted may satisfy the lifecycle in-progress check but cannot certify a current complete navigation answer; any newer committed file is stale, and outside Git only file times apply. Excluded source is outside map coverage, not absent code. Source-changing repairs renew affected checks/build; map-only rebuild is a distinct action.

<!-- anchor: code.doxygen.association -->

## Actual XML association and aliases

- **DOXY-301** MUST: Verify actual XML/index and each covered current entity's own file/location/contract association, including ALL substantive block-tag paragraphs and wrapped summary/structure. Block aliases for modulemap, invariants, usecases, rationale and changes retain continuation content instead of a trailing paragraph-closing ^^; same-line aliases preserve their actual title/text form. Keep qualified relevant project relations and safe prose. Empty file compounds and arbitrary AST/dummy-member quotas prove no association. For shared launcher metadata pin its own source fields and the actual behavioral function location and explicitly disclose ambiguity instead of renaming protected code to satisfy a quota.

## Measured configuration readers

- **DOXY-401** MUST: Use a proven reader for the actual configuration population: quoting, comments, line continuation, = reset and += append, INPUT/FILE_PATTERNS/RECURSIVE/EXCLUDE/EXCLUDE_PATTERNS/symlink rules and the actual project alias titles. Preserve custom aliases and template ordering in authorized migrations. General last-assignment readers and dedicated append-aware alias readers are distinct measured implementations; do not copy inconsistent algorithms or assume all-entity counts suffice. Reader caches, paragraph inverses and fallback behavior remain runtime bindings.
- **DOXY-402** MUST: Read only an entity's own detaileddescription for its titled fields. Where the measured reader dialect applies, invert code spans to backticks, dash entities to --/--- and forced spaces/linebreaks to one space, retaining visible text for other elements; disclose irreversible bold/list renderings rather than invent original markup. Broken or missing child elements/compounds retain scoped fallback evidence. A current index alone does not establish every required entity paragraph.

Example target command (from the target root, after tests): `doxygen Doxyfile`. Inspect its real exit/stdout/stderr, actual configuration-derived XML and source associations; do not infer silent success from a command string. This contract implements no map or migration engine.
