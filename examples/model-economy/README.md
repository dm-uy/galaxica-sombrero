# Model economy: finite semantic cases

These cases interpret the actual [model policy](../../policies/models.md) under existing
[delegation](../../flow/delegation.md), [run-state](../../flow/run-state.md) and
[QA](../../roles/qa.md) authority. They are a bounded independent review matrix, not an executable
selection engine, live adoption probe or measurement of savings. The example adapter is a non-operational fixture.

## Positive decisions

A reviewer reads the candidate clauses independently, records a separate judgment for each case with the actual
clause IDs, conclusion and rationale, and identifies any undefined or contradictory obligation. The required outcomes
below are expectations to challenge, not proof that the policy supplies them.

| Case | Inputs | Requested action | Required conclusion and rationale |
|---|---|---|---|
| C-01 deterministic | A deterministic counting tool completely performs the operation and applicable checks reliably. | Choose how to perform this mechanical step. | Use the adequate tool; no agent is needed for work the tool completes. |
| C-02 routine | An approved plan specifies a bounded explicit transformation; an adequate routine model is available and authorized. | Select tier and context. | Choose sufficient routine capability and relevant inputs; largest-model selection requires task justification. |
| C-03 mixed judgment | Mechanical extraction is followed by an unresolved architecture choice. | Classify the whole assignment or split it. | The whole task requires judgment by its hardest step. Split only into meaningful slices with explicit combined-result ownership, dependencies and retained context. |
| C-04 inadequate with spend | A routine worker demonstrably cannot resolve ambiguity; Debug spend is already two entries of four. | Reassess and switch to an authorized adequate judgment worker, then enter Debug. | Reassess the affected judgment; the next entry is the existing third entry, not a fresh first entry. |
| C-05 ordinary slip | One field typo has a clear cause; there is no evidence of capability inadequacy. | Repair the typo. | Repair within current limits; the slip alone does not mandate escalation. |
| C-06 single-model limits | One adequate model is available; neither effort control nor dynamic model selection is supported. | Bind multiple task tiers and describe the mechanism. | One adequate model may serve them; explicitly declare fixed selection, absent controls and actual authorized fallback. |
| C-07 unknown observation | Requested tier/model/settings are known; observed identity and usage are unavailable. | Record the assignment and assess economy. | Record the request and reason; mark observed identity/usage unknown, label estimates and invent no identity or savings. |
| C-08 evidence reuse | Some evidence has identical input/code/configuration and still applies; a policy artifact changed. | Reuse evidence while validating this candidate. | Explicitly retain only valid unchanged evidence; verify the changed artifact and perform required review/renewed QA. |
| C-09 independent judgment | An author offers self-review of an architecture choice to reduce cost. | Satisfy required independent QA. | Use a separate actor with adequate judgment capability; author self-review cannot satisfy independence. |
| C-10 total economics/context | A small token price brings repeated setup/context/retry cost; a duplicate agent has no distinct necessary work. | Choose adequate resources and brief workers. | Compare total work to a verified result, give sufficient relevant inputs and remove the unjustified duplicate while preserving every criterion and mandatory review. |
| C-11 unavailable authority/effects | A stronger model exists but override permission is absent; prior side-effect completion is unknown. | Switch or replay the prior action. | Availability grants no override or replay authority; follow the existing blocked/escalation route and investigate unknown completion before retry. |

## Five prose mutation controls

Review an authorized scratch copy without git metadata, including all candidate bytes and a SHA-256 manifest. Keep
this case table unchanged. Starting from pristine policy bytes for each control, save the exact carrying clause text
and original hash, apply the real textual alteration, then save mutated bytes/hash and an independent clause-based
judgment. If another policy sentence carries the same obligation, remove or contradict every carrier for that control
and name each one. An unchanged carrier cannot be reported as a detected deletion. Other-subject protections stay
intact; a contradiction with them is a valid named semantic failure.

| Control | Actual alteration in policies/models.md | Witness and required discrimination |
|---|---|---|
| N-01 | Remove MODEL-102's hardest-necessary-step selection obligation and any duplicate carrying policy sentence, including the slice classification in MODEL-103. | C-03 loses its defined classification or contradicts mixed-task adequacy; cite the missing actual obligation. |
| N-02 | Replace adequate-task and total verified-result selection in MODEL-101/102/103/201 with an unconditional cheapest token-price rule, including any other carrying selection clause. | C-03/C-10 wrongly permit inadequate or retry-heavy choices; identify the semantic conflict rather than keyword absence. |
| N-03 | Replace MODEL-403's explicit limitation/fallback obligation with permission to report dynamic tier/effort controls despite absent support, including any duplicate carrying policy sentence. | C-06 permits a false mechanism; cite the contradicted honest limitation obligation. |
| N-04 | Replace MODEL-601's spend-retention obligation with permission to reset counters on model/worker/context switch. | C-04 permits a fresh first entry after prior spend, contradicting existing state/delegation authority. |
| N-05 | Replace MODEL-603's independent-actor obligation with author self-review as equivalent to required independent review. | C-09 wrongly satisfies independent judgment and contradicts the existing QA contract. |

After each control, restore the exact pristine bytes. Require byte equality and the original SHA-256, then rejudge
the pristine witness independently. Record original/mutated/restored hashes, exact text, actor identity, candidate
identity and case verdicts. The original delivery tree's before/after hashes must match. An expected scratch rejection
is evidence of discrimination; a control that does not fail its witness needs diagnosis, not a relabeled pass.

## Evidence boundaries

Structural conformance checks cards, norms, resolving calls and adapter coverage. These eleven separate judgments and
five real prose controls test finite policy meaning. Runtime adoption and cost/time improvements need their own actual
observations. Required regression, CLI, publication and documentation-build checks still run against the delivered
candidate; this matrix does not replace them.
