# Contextual project experience

<!-- anchor: process.learning.local -->

## Experience and retrieval

- **LEARN-101** MUST: Save useful failures, successful remedies and corrected beliefs in project notes with task/scenario, date/version/context, attempted action, observation/evidence/source, confirmed cause versus hypothesis, verified remedy or its absence, applicability and recheck condition. Unknown inputs stay unknown.
- **LEARN-102** MUST: Distinguish measured, computed, estimated and unverified findings from owner requirements and agent proposals. A timeout alone does not prove library unsuitability; a small example does not prove broad effectiveness.
- **LEARN-103** MUST: Link relevant experience from TASKS and only current warnings from HANDOFF. For unfamiliar work locate matching notes; avoid whole-archive reads. Add an index only for an actual retrieval need, without duplicating conclusions.
- **LEARN-104** MUST: Before reuse compare version/context. Recheck uncertain or changeable integration knowledge against current authoritative documentation/schema or actual task evidence. Model recollection alone is not current proof; unavailable checks remain explicit.
- **LEARN-105** MUST: Preserve dated observations while marking outdated/superseded conclusions and linking fresh evidence. A binding library/provider choice links the evidence note and follows the decision lifecycle.
- **LEARN-106** MUST: Promote cross-project lessons only as source-backed candidates with context/limits under the receiving store's authority. No automatic global rule, curated truth, external write or implemented memory engine follows from a local finding.
