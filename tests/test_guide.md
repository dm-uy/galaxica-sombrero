# Test guide

Current source2.2 has73 members,27 skills,six helpers and six role carriers. Sections before the C2 heading retain historical M19/M25A/C1 input frames, observations and acceptance tables, including original47/23/two counts; these are not current package composition. The current C2 section governs current fact/scope verification, including the sole approved Claude test exception.

This guide maps every acceptance criterion of the meta-framework repository to the tests that prove it, lists the commands
that run them, and names the trace lines an agent reads to follow a run. It is not a neutral file: it lives under `tests/`
and carries no card.

## Commands

| Command | What it does | Expected result |
|---|---|---|
| `python3 -m pytest tests -s -v --log-cli-level=INFO` | Runs the whole suite with the trace lines of every test printed before its asserts. | Every test passes; the Anti-Loop counter is reset to 0. |
| `doxygen Doxyfile` | Builds the code map of `tools`, `bin` and `tests` into `doxygen_output/xml/`. | Exit 0 and 0 lines of output; the XML holds a compound for `tools/conform.py` and one for `bin/conform`. |
| `bin/conform self --deny-list PRIVATE_DENY_LIST` | Checks this repository against the owner's private deny list (the file is kept outside the repository). | Exit 0; the summary line is quoted by the finalize phase. |
| `bin/conform adapter examples/adapter.example.json` | Checks the example adapter against this repository. | Exit 0; rows for the three modes, the vendored entry PASS. |

The suite needs Python 3.9 or newer and the standard library, plus `pytest` and `doxygen` on the path. Nothing else is
installed. The launcher and the tests set no module path themselves: `pytest.ini` sets `pythonpath = tools` once.

## Anti-Loop protocol

`tests/conftest.py` keeps a counter of consecutive red sessions in `tests/.test_counter.json` (ignored by git). A green
session resets it to 0. A red one raises it and prints the advice for that attempt:

| Attempt | Advice |
|---|---|
| 1 and 2 | The checklist of the common errors of this project. |
| 3 | Stop guessing: read this guide, `checks/conform.md` and `FORMAT.md`, build the code map, read the trajectory of the failing test. |
| 4 | A looping warning: write at least two hypotheses and change the approach, not the detail. |
| 5 and later | Stop: report the failing tests, the trace lines and the hypotheses tried, and ask for direction. |

The checklist of the common errors: a scanner pattern that matches its own source line (build every pattern and canary from
fragments); a log line that carries content (paths, counts and fingerprints only); a fenced block not closed in a Markdown
file; CRLF not normalised before a hash, a comparison or a card read; an argument error escaping as an exit instead of the
usage refusal; a module path changed from a test.

## Trace lines to read

Every test prints `[IMP:9][<test name>][<BLOCK>]` lines before its asserts, and the tool's own trace is collected by the
`ldd_trajectory` fixture. The lines that tell a run's story:

| Marker | Meaning |
|---|---|
| `[run_self][VERDICT]` | The verdict of a self run: exit code, failure and warning counts, neutral files read. |
| `[run_adapter][VERDICT]` | The same for an adapter run. |
| `[run_adapter][REFUSAL]` | An adapter run that could not judge: the rule of the refusal and no more. |
| `[canary_probe][BITE]` | The scan's run-time canary probe: how many patterns and tokens, and whether each matched its canary. |
| `[scan_tree][FINDING]` | One scan finding: rule, file, line, fingerprint; never the value. |
| `[check_vendored][DRIFT]` | The comparison of a vendored copy with the spec: path, whether the hash is fresh, and the number of section differences. |
| `[main][EXIT]` | The exit code the frontend returns. |

Importance 1 to 3 is a trace of a step, 4 to 6 the flow, 7 to 8 a read at a boundary, 9 to 10 a verdict or a failure.
