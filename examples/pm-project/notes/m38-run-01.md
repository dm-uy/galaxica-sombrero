# M38-RUN-01 — the first real methodology run (prepared, not yet executed)

This is the executable acceptance run for the DSH package. It exists because everything proved so far is structural: the adapter conforms, the package tests pass, and the bundle composes a real layer in the live `web` profile whose row resolves to a 27-entry skill root. None of that is a run, and no session has yet loaded a methodology skill through this package.

## Why it has not run yet

Two independent walls, both worth recording:

1. **The live session that prepared this work predates the installation.** A session's skill catalog and preset are fixed when the session is created, so the session that installed the bundle still carries its old catalog. The harness composes a fresh preset on the next turn or the next session, which is when the catalog appears.
2. **No LLM route is available to a headless probe from a shell.** `dsh --profile <probe> -` on a scratch profile that mirrors the live one fails with `MISSING_CREDENTIAL: llm-deepseek: no API key for provider route "deepseek-official"`. The live profile reaches the same provider successfully because the Web host stores the key in memory through the credentials service; that key is not present in a child shell's environment, and reading the credential store to extract it is not permitted. A headless run therefore needs either an owner-exported key in the launching environment or an owner-driven session.

So the run below is written to be executed by the owner's own session, where the route already works.

## Prerequisite

A **fresh** session in the Web GUI (send any new message after this work landed). Restarting the profile is not required for a new session, because the profile already reloads its configuration live.

## Probe 1 — the catalog and the base directory

Ask the session to load one skill and report what the harness told it:

```text
Call the `skill` tool with the exact name `pm`. Then tell me, exactly as reported:
(1) the "Base directory for this skill" line, (2) every skill name visible in your
session catalog, sorted, and (3) which of pm, pm-bootstrap, pm-plan-batch,
pm-run-batch, pm-handoff, feature-dev, brainstorm are present. Read nothing else.
```

**Pass:** the base directory is this checkout's `implementations/dsh/skills/pm` directory, and all seven names are present. The identity that matters is that it resolves into the canonical checkout rather than a cached copy; compare it with the path printed by the `--dump-config` procedure in the package README. **Fail:** the skill is absent, or the base directory points anywhere else. Record the exact output either way; a partial catalog is a real finding, not a rounding error.

## Probe 2 — the bounded smoke

`implementations/dsh/examples/smoke-spec.md` is the package's own reusable, low-risk specification: an inventory report with exact target paths and source-derived refusals. Run it through the package the way the package's README prescribes, and keep the artifact and the command receipts.

**Pass:** the report's paths, counts and refusals all derive from the actual target, and any check the run declares ran actually ran. **Fail:** any claimed count or path that the target does not support, or a check reported as passed without its output.

## Probe 3 — the first real task

The honest first consumer task is this repository's own next unit of work, because its records, gates and evidence rules are already established here: the DSH package has a queued behavioural-acceptance task, and the pending `claude/m37-claude-parity` branch is a foreign writer's work that must be left alone.

Run `pm` on this repository and let it recover state from the four current records, then execute exactly one bounded task with the flow that task warrants. Record the run state, the evidence and the limitations in the existing homes.

**Pass:** the run recovers the actual current state without being told it, names the real next action, respects the writer boundaries, and leaves its evidence in the owned records. **Fail:** an invented state, a fabricated evidence pointer, or any edit outside the granted paths.

## What this run does and does not establish

It establishes that a fresh session discovers the package's catalog, loads a named protocol on demand from the canonical checkout, and can carry one bounded real task through the methodology with its records updated. It does **not** establish role isolation, because the bundle ships no preset; it does not establish a full Bootstrap→Finalize feature flow; and it does not establish any model-economy claim.

## Evidence to retain

Paste into the M38 record: the three probe outputs verbatim, the smoke artifact path, the run-state ledger path, the commands with their exit codes, and every failure or partial result. A green summary from a probe is not evidence; the probe's own output is.
