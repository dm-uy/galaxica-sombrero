# Bootstrap

Minimum preparation connects actual project facts and the original human goal to the next authorized role. Applicability does not grant writes or technical authorship. Existing role, permission, reconnaissance, return and project contracts govern this interface.

<!-- anchor: process.bootstrap.classification -->

## Preparation applicability and original inputs

- **BOOT-101** MUST: Read the actual accessible code and source facts before classifying preparation. Read the actual applicable hidden and project agent instructions before preparing inputs. Read the actual complete brief and durable project state before deriving preparation inputs. Inspect actual Git and applicable map facts and declare the available access scope.
- **BOOT-102** MUST: Classify an existing executable codebase as existing code requiring applicable migration or reconstruction. Missing durable documents alone never make an existing codebase greenfield. Use new-product preparation only for a genuinely new product supported by actual inputs.
- **BOOT-103** MUST: Treat an owner-requested conventions migration as its actual bounded preparation trigger. Require a matching bounded preparation grant before preparation writes.
- **BOOT-104** MUST: Keep spine inventory read-only. Return discovered preparation needs to the authorized parent. Obtain separate preparation write authority for the actual affected files.
- **BOOT-105** MUST: Read the complete original brief rather than substituting a guessed summary. Read every original non-negotiable constraint before preparing choices.
- **BOOT-106** MUST: Recover settled answers and choices with their actual decision provenance. Reuse matching settled answers without redundant re-asking or silent replacement. Stop and route only genuine material ungranted gaps to their decision owner.
- **BOOT-107** MUST: State what the product does and the original human purpose it serves. State the actual intended audience. State one falsifiable user-visible first value and its observable pass condition.
- **BOOT-108** MUST: Retain every binding original non-negotiable in the prepared handoff.

<!-- anchor: process.bootstrap.measured-inputs -->

## Measured inputs before dependent work

- **BOOT-109** MUST: Carry source-backed settled stack, storage and transport choices as inputs. Carry the rationale and binding constraints for those settled technical choices. Verify load-bearing version facts when relevant before handing them to the next role.
- **BOOT-110** MUST: Carry the smallest approved included MVP boundary before Code. State deliberately deferred capabilities and actual dependencies. Settle the applicable boundary before coding rather than expanding it during implementation.
- **BOOT-111** MUST: Name the real probe transport, path and delivery sink required by the next role. Name the probe scenario and measurable pass condition. Disclose actual probe access limits and unverified outcomes.
- **BOOT-112** MUST: Complete measured current reconnaissance before drafting a dependent specification. Hand off the actual reconnaissance path, measurements, evidence and limitations.
- **BOOT-113** MUST: Preserve every actually required relevant reconnaissance lane and original requirement quantifier. Verify relevant load-bearing external facts against actual sources. Distinguish actual operational input from fixture or synthetic input explicitly.

## Authorized output, prerequisites and truthful handoff

- **BOOT-114** MUST: Seed only applicable missing durable or specification inputs within explicit existing file authority. Use the actual dictated one-truth locations for each prepared input. Preserve existing content and history without overwriting them. Leave detailed document templates and lifecycle bodies at their declared later homes.
- **BOOT-115** MUST: Preserve the original human owner intent in prepared inputs. Carry the actual initial checkpoint into the prepared handoff.
- **BOOT-116** MUST: Discover actual Git state and any applicable initialization need. Require matching actual permission for Git initialization or commit, or return the missing grant explicitly. Keep integration authority with the authorized parent rather than the inner preparer.
- **BOOT-117** MUST: Resolve applicable initialization and ignore-hygiene prerequisites from actual project inputs. Preserve existing ignore and exclusion rules. Return missing hygiene as an explicit unresolved gap with its owning next action. Leave detailed ignore patterns and initializer implementation to the declared later or runtime homes.
- **BOOT-118** MUST: Exclude secret values from prepared artifacts and logs. Respect actual concurrency and single-writer constraints. Preserve foreign changes and their existing truth.
- **BOOT-119** MUST: Identify the actual needed baseline, map and checker configuration. Associate the actual source and map using project-resolved paths. Report missing required configuration explicitly as unavailable. Leave detailed baseline, map and checker generator implementations at their declared homes.
- **BOOT-120** MUST: Run a checker only when it is actually available, applicable and authorized. Retain the actual measured checker output and input identity. Retain every remaining rule failure or gap and its owning next action. Never report an unavailable or failed required check as PASS.
- **BOOT-121** MUST: Route an actual in-scope preparation defect through the existing authorized repair path. Stop dependent content-losing migration instead of deleting truth to force readiness. Stop dependent work on an unconfirmed material decision and return its owner.
- **BOOT-122** MUST: Return actual prepared artifact identities. Return measured outcomes and every remaining gap or refusal. Return the owning scope and next authorized action. Use existing return contracts and keep concrete result approval separate from preparation completion.

## Assigned technical authorship

- **BOOT-123** MUST: Convey settled constraints as inputs to the next assigned role. Leave technical architecture authorship to the assigned Architect. Leave implementation and repair to assigned Code and Debug roles.

Preparation supplies these inputs through the existing [PM](../roles/pm.md), [reconnaissance](reconnaissance.md), [role-return](../protocols/role-returns.md) and [delegation](../flow/delegation.md) interfaces. A missing applicable prerequisite is an explicit gap with its owner and next action, never an invented ready result. Scope permission, preparation completion and concrete-result integration remain separate.

Detailed [specification](specification.md), [document and template](../documents/conventions.md), [code-layer](../code/exoskeleton.md) and [prompting](../prompting/grace.md) bodies retain their declared homes. Runtime-specific installation and initializer mechanisms follow actual adapter adoption and separate authority; this minimum interface implements no engine or universal file path.
