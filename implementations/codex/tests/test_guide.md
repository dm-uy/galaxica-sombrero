## Inputs, isolation and commands

The four package modules import the real run_state and visual_gate_lint through the package pytest.ini's two explicit pythonpath directories. No sys.path mutation or donor import is used. Actual complete package47 and adapter-declared neutral71 source bytes are copied read-only into pytest tmp_path fixtures; only owned fixture target/state/source copies change. Fixture role envelopes are structural cases, never authentic owner approval, independent QA or native execution. CLI cases launch the real shipped helper and retain full argv/cwd/stdout/stderr/exit and saved state. Pure helper logic is tested directly, not through subprocess substitutes.

From the complete canonical source root, use the actual planned command:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -c implementations/codex/pytest.ini implementations/codex/tests -p no:cacheprovider -s -v --basetemp OWNED_ABSENT_PACKAGE_ROOT
```

The caller resolves the owned absent basetemp and retains actual source/config/environment/counter identity privately. Package tests do not reset the root's protected test-session hook or parent Debug allowance. The root separately runs its full unchanged common commands and final map. From implementations/codex, after required tests/documentation checks, run `doxygen Doxyfile`; use current XML/index/source/config and every entity's own fields/paragraphs/location, including wrapped module summary/structure. test_own_helper_trace_and_map builds a real map only inside an owned copied package fixture; it does not replace the final Code/Finalize map for the actual canonical candidate.

Expected trace: successful owning critical decisions emit IMP9 before accepted results; expected rejections emit their owning IMP10 before propagation or CLI exit2. Tests expose real IMP7–10 and every ERROR/CRITICAL before assertions. Each of thirteen failure-capable callers declares its own exact ordered profile before the refusal: logger, numeric level, owning function/block, complete safe cause, exception class and exact cardinality. The complete actual error population must equal that profile; legitimate nested propagation remains expected, while extra same-module or foreign-module errors and criticals refuse. No profile is inferred from observed logs or a producer allowlist. CLI stdout remains its declared parseable JSON/report, stderr carries actual safe trace. Direct trace capture is supplemented by actual child streams/file readback. The visible suite and complete relevant logs are audited by the parent/independent QA; a green token is not semantic evidence.
