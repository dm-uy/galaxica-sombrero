# TASKS project form

<!-- anchor: documents.templates.tasks.form -->

## Project record form

The following fenced text is a drafting form, not live neutral metadata or consent. Use actual project instructions, evidence and vocabulary.

```markdown
---
type: Tasks
title: "TASKS — <current task or bounded batch>"
status: <proposed/active>
generated: { by: "<author>", at: "<actual UTC time>" }
---

# Authorization

<Who granted what, actual instruction/decision, scope and reserved decisions. A batch covers only its specified tasks. Use any additional frontmatter required by the project's conventions.>

## <T-ID> <Concrete deliverable>

- State: <project vocabulary>.
- Goal/route: <step and purpose>.
- Grant: <actual authority, or explicitly proposed>.
- Deliverable: <reviewable artifact/outcome>.
- Scope: <allowed artifacts/actions and exclusions; writer owner>.
- Inputs: <necessary current sources/revisions and relevant experience-note pointers; assess their applicability>.
- Done when: <observable finish conditions appropriate to the work type>.
- Stop and ask when: <exceptional owner decision or missing mandatory evidence>.
- Dependencies: <none or links>.
- Action outcome: <none/pending/known/unknown; intent and observed effect pointer; inspect before retry>.
- Evidence/result: <actual result/review pointer; not run is explicit>.
- Next disposition: <next authorized step, pending owner choice or retained deferral>.

# Retained work

<Previous packet/result pointers and unfinished work disposition. Preserve this packet before replacing it; no false claim of merge/acceptance.>

# Activation, dispatch and assessment

<Packet/batch identity, adopted profile and state vocabulary, dependency order and permitted independent lanes; actual matching approval identity/scope; readiness checks; current route/task/handoff reconciled on activation under local storage policy. Unresolved go/no-go leaves its dependent work unactivated.>
<Delegation, if applicable: one writer per exact path, allowed output, actual method and independent verification owner. Software class/map/flow and decision-ID reservation apply only where already required.>
<Per check: required result, command/review identity, actual outcome and limits, skipped/not-run/blocked reason and remaining verification owner. A successful cycle cannot cover omitted checks.>

# Close and carryover

<Completed artifact assessment, reserved acceptance/integration, retained failed/held/unfinished rows with reason/return condition, archive pointer and next authorized disposition. Preserve the earlier complete packet before replacing current work. Cleanup lists only run-owned resources, ignored/foreign ownership, preserved contents and matching cleanup authority.>

```

No improvement experiment, candidate ingestion or measured effectiveness claim follows.
