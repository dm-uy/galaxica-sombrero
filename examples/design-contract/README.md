# Design contract fixtures

PURPOSE: Make the minimum plan/XML/reference contract reviewable through actual generic bytes.
RATIONALE: Greenfield and brownfield expose different reference and comparison conditions; separate negative files discriminate parse, identity, link, map and coverage defects.
VERIFICATION CONTRACT: Read PLAN-101–104/301–308/401–404 and GRAPH-101–303/401–403, the actual two plans, XML, map and identity files. Run `python3 -m pytest tests/test_design_contract.py -s -v` from the repository root. This is a finite fixture suite, not a callable general validator or live product/harness.

Greenfield has three changed modules and all three approved BR checks; only prior-architecture comparison is GREENFIELD_WEAK. Brownfield has two changed modules, repeated annotation and Link metadata, and a typed existing reference to a real entity in existing-map.xml. The source registry identifies actual map/source bytes and exact source line. Authentication/freshness of a real caller's external facts remains the caller's evidence duty.

The plans include actual traceability, structural and sequence diagram source faithful to XML/data flow. Brownfield uses its verified unchanged lookup through order and retains two changed definitions. The plans state scenario requirements, all six sections, purpose/rationale/verification, ordered data flow, conditional delivery sink/mechanism and literal verification commitments. The hypothetical product operations are future commitments; only the shipped XML parser/hash/lookup checks actually run here. There is no fake product implementation whose existence is offered as proof.

Negative files change exactly the relevant field or element. Malformed XML fails parsing. Duplicate identities differ from legal repeated reserved tags. Normalization-collision.xml gives distinct FILE basenames pkg.reader.py and pkg reader.py whose underscore normalization produces the same actual entity definition tag pkg_reader_py. Dangling local links fail without implicit external conversion. Missing/stale maps, stale source identity and fabricated existing entity fail reference readiness. Missing/empty/non-BR satisfaction, unknown membership and uncovered BR are independent failures, including greenfield.
