# Navigation

This contract describes applicable source authoring and evidence duties under the target rules. Actual runtime mechanisms remain declared adaptation points; textual completion supplies no operational adoption claim.

<!-- anchor: code.navigation.order -->

## Semantic top-down order

- **NAV-101** MUST: Start project-code navigation with the semantic GREP_SUMMARY/STRUCTURE overview, then relevant contracts and nodes; consult a current generated Doxygen map before raw source for relationships and unmarked areas. Source markup supplies semantic truth, generated XML maps it and architecture prose describes intent. Use the bounded read-only Searcher for deep marked-code work; keep unmarked/vendor exploration distinct. Jump from actual function/block logs to their matching source steps and use dense domain/concept/technology terms rather than sentence queries.

<!-- anchor: code.navigation.fallback -->

## Read-only fallback and honest gaps

- **NAV-201** MUST: State the actual answer source and precise fallback reason. Missing configuration/index, stale or unparseable map, excluded source, unmigrated contract, absent OWN entity paragraphs or unmapped nested symbol remains GAP/refusal for the unavailable map claim. Fall back to source only where it answers and disclose omissions; isolate broken compounds. Read-only navigation never executes inspected code or writes source/map: request an authorized parent refresh. A degraded source answer never proves a current complete map; unknown evidence is not N/A, which requires evidenced bounded absence.

<!-- anchor: code.navigation.relations -->

## Declared relations versus observed calls

- **NAV-301** MUST: Separate semantic declared relations from observed calls. Caller/callee evidence comes from the actual code name scan, never from Doxygen declarations or uses alone. Label by-name uncertainty and same-name collisions; resolve local import aliases only within measured detector capability, attribute nested calls to their own definition, omit self-edges and duplicate proofs, and list ambiguous matches rather than guess. Empty class caller lists do not prove non-instantiation. No full dynamic call-graph completeness follows.

<!-- anchor: code.navigation.identity -->

## Current own-entity provenance

- **NAV-401** MUST: Bind each map answer to the requested entity by current source bytes/identity, its actual file/location and its OWN contract paragraphs, never coincident names or nested neighbors. Read actual Doxyfile paths, titles and covered population; parse index first and only relevant compounds, retain all continuations and current-form precedence, and disclose irreversible rendering differences. Shared dummy metadata needs pinned own source fields plus actual behavioral location and disclosed collision ambiguity. Empty compounds, shared anchors or aggregate counts alone cannot certify association.

<!-- anchor: code.navigation.runtime -->

## Declared detector boundary

- **NAV-501** MUST: Keep navigation tool implementation at the declared runtime boundary. Where the source codemap dialect is supplied, preserve its actual stdout and exit contract: 0 answered, 1 not found, 2 could not run; five labelled file lines with source second and (none) for missing values; one block per ambiguous symbol; supported Python file/function/method/class kinds and path forms. Preserve lazy per-run caches, skipped unparseable-source disclosure, dotted/suffix/same-file resolution, restricted local from-import alias handling, exact source I/O/errors/order/regexes and detector scope. No universal shell permission, hidden coverage gap or tool port follows.

<!-- anchor: code.navigation.dialect -->

## Snapshot-first runtime dialect

- **NAV-601** MUST: Retain an invoked runtime snapshot-first dialect: index.xml FIRST and ONLY, then bounded per-compound XML; whole-snapshot reads are forbidden there, stale findings stay unverified-stale and unavailable-map fallback is explicit. Its measured size rationale is historical attribution. Neutral source-markup-first/map-before-raw navigation follows the owning project precedence; this does not automatically change another runtime's dialect.

<!-- anchor: code.navigation.maintained-graph -->

## Conditional maintained post-code graph

- **NAV-701** MUST: When a maintained post-code graph is actually part of the target contract, update added, moved and deleted file entities in the same change. Show the load-bearing top-level relations needed to orient across the represented files, retaining their actual source-backed endpoints and meaning; node coverage alone is not that relation overview. Compare the declared tree population against graph coverage, check unique normalized identities and every local target, and record unfinished omissions INSIDE the affected graph rather than silently leave it stale. Distinguish known gaps from intentionally excluded generated/runtime populations and never certify partial coverage as complete. Actual source/generation evidence is required; counts and dangling-link checks alone cannot establish whole-tree coverage.
- **NAV-702** MUST: Keep the optional maintained post-code KnowledgeGraph/AppGraph distinct from the canonical planned DraftCodeGraph in the development plan and from the Doxygen semantic map. Full generic taxonomy/weights/authoring grammar is now authored in [graph](../protocols/graph.md); external knowledge/storage engines retain their exact runtime or later subject homes; this interface neither implements them nor creates a competing architecture source.
